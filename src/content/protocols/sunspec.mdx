SunSpec is not a wire protocol of its own. It is a set of standard **models** (register maps) that distributed energy resources expose over Modbus: inverters, meters, batteries, string combiners and more. A device starts its map with the `SunS` marker at a base address, followed by a chain of models, each identified by a number (for example 103 for a three-phase inverter). Values carry **scale factors**, so a raw register becomes watts, volts or amps only after decoding.

## Where you meet it

- Solar inverters and hybrid inverters
- Battery storage systems and their energy management
- Revenue and production meters on DER sites

## Quickstart

### From the command line

[sunspecctl](/projects/sunspecctl/) is a single binary for Linux, macOS and Windows. Download it from [GitHub Releases](https://github.com/otfabric/sunspecctl/releases), then:

```sh
# Is this a SunSpec device, and at which base address?
sunspecctl detect --url tcp://192.168.1.100:502

# Which SunSpec models does it implement?
sunspecctl models --url tcp://192.168.1.100:502

# Copy the device into a file, and serve that copy as a simulated device
sunspecctl capture --url tcp://192.168.1.100:502 -o device.json
sunspecctl serve --file device.json --url tcp://127.0.0.1:1502
```

`modbusctl client sunspec probe` gives a quick check from the Modbus CLI too.

### In a window

[SunSpec Explorer](/projects/sunspec-explorer/) shows every model a device exposes, fully decoded, and polls, records and exports it without ever writing to the device. Run it as a desktop application on macOS, Windows or Linux, or as a daemon on a gateway with the same interface in your browser. Download it from [GitHub Releases](https://github.com/otfabric/sunspec-explorer/releases/latest).

### From Go

```sh
go get github.com/otfabric/go-sunspec
```

Discover the device and print the scaled points of a three-phase inverter model (abridged from the go-sunspec README):

```go title="main.go"
client, _ := modbus.New(modbus.Config{URL: "tcp://192.168.1.100:502"})
if err := client.Open(); err != nil {
	log.Fatal(err)
}
defer client.Close()

device, err := sunspec.Discover(ctx, client, &sunspec.DiscoverOptions{UnitID: 1})
if err != nil {
	log.Fatal(err) // errors.Is(err, sunspec.ErrNotSunSpec) when the device is not SunSpec
}

inverter, err := device.ReadModelByID(ctx, 103) // three-phase inverter
if err != nil {
	log.Fatal(err)
}
for _, p := range inverter.Group.Points {
	if p.Implemented && p.ScaledValue != nil {
		fmt.Printf("%s = %g %s\n", p.Name, *p.ScaledValue, p.Units)
	}
}
```

The same model definitions work the other way round: `sunspec.NewServer` builds a device from point values by name and serves it through go-modbus, as a simulator for an EMS or SCADA integration, or as the SunSpec interface of your own equipment. See [Serving a device](/docs/protocols/sunspec/library/#serving-a-device).

## What go-sunspec supports

| | |
|---|---|
| Discovery | Finds the `SunS` marker at common base addresses and walks the model chain |
| Models | 112 built in: inverters, meters, nameplate and settings, multiple MPPT, DER (701–715), storage (801–809), environmental sensors, string combiners |
| Decoding | Every SunSpec point type, scale factors applied, unimplemented points flagged, enums and bitfields by name |
| Unknown models | Discovered and returned with raw registers |
| Changed devices | A model whose header no longer matches discovery is reported as `ErrModelChanged`, never decoded with a stale layout |
| Serving | A SunSpec device in memory, built from point values by name, served through go-modbus over TCP or TLS; accepts client writes to writable points and live updates |
| Encoding | `EncodeModel` builds a model's registers from point values, the inverse of `DecodeModel` |
| Transports | Every go-modbus transport: TCP, RTU, ASCII, TLS, UDP and serial bridges |
| Go version | 1.23 or later, with go-modbus v1.5.0 or later |

<Callout type="caution">
SunSpec control models (settings, DER curves) change how an inverter or battery behaves on the grid. Read first, develop against a served device, and only write to equipment you are authorized to operate.
</Callout>
